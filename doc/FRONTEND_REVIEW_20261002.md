# 前端视觉与操作审查（2026-10-02）

## 范围与结论

审查播放器、移动端滑轨、设备设置弹窗、轮询刷新和小屏布局。保留流体光域视觉方向。本轮解决下列源码确认的操作缺陷；并非完整商业发布认证。

## 已整改

| 优先级 | 问题 | 整改 |
| --- | --- | --- |
| P1 | 自定义手柄绕过 disabled/inert | 手势入口及提交前校验禁用状态，禁用手柄不可触摸 |
| P1 | 取消拖动仍提交音量或延迟 | cancel/lost capture 回退初值；仅正常结束且数值变化时提交 |
| P1 | 轮询重建设备卡片关闭编辑弹窗 | 弹窗打开期间延后重建，关闭后按最新状态刷新 |
| P2 | 滑块显示位置与拖动计算不一致 | 显示与计算统一按两端各 10px 的有效轨道 |
| P2 | 延迟按钮更新数值但自定义手柄停在旧位置 | 显式同步手柄；拒绝空值和非有限数字 |
| P2 | 封面失败后每轮询重发请求并闪烁 | 按请求地址去重；同一地址失败后使用占位图 |
| P2 | 直播音源显示可操作进度 | 时长未知时禁用跳转 |
| P2 | 队列后台刷新失败产生未处理异常 | 捕获错误并更新连接状态 |
| P2 | 窄屏控制行拥挤、弹窗可能超高 | 压缩横向间距，弹窗限高并允许内部滚动 |
| P2 | 次要文字对比度较低 | 增加曲目信息与时间文本亮度 |

## 验证

- 现有 37 项 Python 测试通过；三个修改的 JS 文件语法检查通过。
- 保留 PC 原生 range 和移动端仅拖动圆点的操作约定。
- 未进行本轮真实 iOS/Android 手势、屏幕阅读器、完整播放器业务及长期多端并发验收；上述项目不能视为已通过。

## 后续发布门槛

- 320/390/768/1440px 视口：播放、队列、歌单、电台、曲库与设备弹窗截图及溢出检查。
- 真机覆盖拖动取消、系统手势中断、滚动穿过轨道、旋转屏幕、AirPlay 禁用状态。
- 使用稳定模拟接口覆盖多端同步、请求乱序、重复点击、断网恢复及认证失效。
- 设备弹窗目前延后整体刷新，打开期间设备状态不会实时更新；后续可改为逐字段同步而保持编辑草稿。
