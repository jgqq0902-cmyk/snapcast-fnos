## P0 — Light Theme 存在明确的可访问性问题

当前：

```css
--bg: #f4eee6;
--surface-solid: #fbf7f1;
--brand: #d18a59;
```

同时 `--brand` 被大量用于 **9px / 10px** 小文字：

```css
.page-header p       10px
.zone-head small      9px
.settings-card small  9px
.group-form small    10px
```

按当前颜色直接计算：

* `#d18a59` / `#f4eee6` ≈ **2.43:1**
* `#d18a59` / `#fbf7f1` ≈ **2.63:1**

WCAG 2.2 AA 对普通文字要求至少 **4.5:1**。([W3C][1])

所以这不是单纯的“颜色审美问题”。

### 建议

不要换掉铜橙品牌色，而应该拆分：

```css
--brand
--brand-text-light
--brand-text-dark
--brand-surface
--brand-border
```

铜橙继续用于：

* 图标
* 大面积装饰
* selected background
* progress
* glow

但 Light Theme 的 9–12px 标签换成更深的铜棕。

这是商业发布前应完成的项目。

# 二、还有一个值得立即修复的登录 UI 问题

现在：

```javascript
dialog.addEventListener(
  "cancel",
  event => event.preventDefault(),
  { once: true }
);
```

也就是说：

**第一次 ESC 被阻止，但监听器随后被删除，第二次 ESC 可以关闭登录 Dialog。**

而 `logout()` 又只是：

```javascript
state.auth.authenticated = false;
bootstrapped = false;
openLogin();
```

没有清空已经渲染出来的 Zone/Client 数据。

这会造成一个不够商业级的状态：

> 用户退出 → 登录框出现 → 连续 ESC → 登录框消失 → 上一次设备状态仍可能显示。

API 本身仍有认证保护，所以这不等于后端认证绕过，但属于**前端认证边界和隐私状态泄露问题**。

建议登录 Dialog：

```text
authenticated == false
    ↓
不可 dismiss
    ↓
ESC 永久阻止
backdrop 不可关闭
没有 close button
```

同时 Logout 时：

```text
clear player iframe
clear zones
clear sources
clear user-sensitive DOM
reset route
```

# 三、字体目前还没有达到商业产品的一致性

现在使用：

```css
"Avenir Next",
"Noto Sans CJK SC",
"Microsoft YaHei",
sans-serif
```

标题：

```css
"Iowan Old Style",
"Songti SC",
Georgia,
serif
```

这在：

* Windows
* macOS
* Android
* Linux
* FNOS WebView

之间呈现会明显不同。

尤其：

* Avenir Next → Windows 通常没有
* Iowan Old Style → Windows/Linux 通常没有
* 宋体 / Georgia 的 fallback 字宽差异很大

最终会造成同一产品在不同客户端“像不同设计”。

### 商业级建议

建立固定的：

```text
Display
Title
Body
Label
Caption
Mono / Technical
```

6 级 Typography Token。

例如：

```css
--font-ui
--font-display

--text-display
--text-title
--text-body
--text-label
--text-caption

--weight-regular
--weight-medium
--weight-semibold
```

而不是继续在组件内部写：

```text
9px
10px
11px
15px
22px
24px
28px
32px
58px
```

# 四、现在最缺的其实是“状态设计”

设备首页现在主要只有：

```text
正在读取设备…
未发现播放房间
服务在线
部分异常
连接中断
```

商业产品至少应该正式设计：

```text
Loading
Skeleton

Empty
没有发现设备
→ 如何添加设备？

Offline
网关连接中断
→ 重试
→ 查看诊断

Partial failure
3 台设备中 1 台离线

Unauthorized
登录过期

Mutation pending
正在调整播放组

Success
已完成

Failed
失败 + 原因 + 重试
```

尤其 Empty State 现在只有：

> 未发现播放房间

商业版本应该是一个完整组件：

```text
        Speaker Illustration

        暂未发现设备

确保 Snapclient 已启动，并与当前
Snap / Room 网关位于同一网络。

[重新扫描]   [查看帮助]
```

这类改造对“商业感”的提升，实际上比再增加阴影和渐变明显得多。

# 五、交互视觉系统还没完整

目前比较明显定义了：

* icon button hover
* Stop All hover
* disabled
* focus outline

但还没有系统性定义：

```text
Default
Hover
Pressed
Focus
Selected
Disabled
Loading
Danger
Success
```

例如音源 Chip 当前主要只有：

```text
normal
active
```

设备管理按钮主要靠颜色区别。

### 建议形成统一 State Layer

例如：

```css
--state-hover
--state-pressed
--state-selected
--state-focus
--state-disabled

--motion-fast: 120ms
--motion-normal: 180ms
--motion-slow: 280ms
```

所有 Button / Chip / Card / Navigation / Slider 统一处理。

这样商业产品的“手感”才会统一。

# 六、需要补齐 Accessibility Semantics

目前视觉 active 已经存在，例如：

```html
<button class="active" data-route="devices">
```

但是没有：

```html
aria-current="page"
```

音源：

```html
<button class="active">
```

也没有：

```html
aria-pressed="true"
```

Dialog 也建议增加明确：

```html
aria-labelledby
aria-describedby
```

当前 Native `<dialog>` 是一个很好的基础，不需要换组件库，只需要把语义补完整。

商业版验收目标建议直接定：

> **WCAG 2.2 AA**

# 八、“立即停止”现在视觉权重偏高

当前页面顶部：

```text
[立即停止] [管理播放组] [刷新]
```

其中 Stop All：

```css
background: var(--danger);
font-weight: 800;
box-shadow: red glow;
```

结果是进入首页后，最强视觉焦点可能不是：

> 房间 / 当前播放内容

而是：

> 红色“立即停止”

功能本身应该保留，但商业级 UI 可以考虑：

```text
管理播放组     ⟳     ⋯
                       └─ 停止所有音源
```

或者只有“存在正在播放的音源”时才增强 Stop All。

也就是：

> **Destructive Action 不应该长期成为整个首页最高视觉层级。**

## 最终判断

当前 `ca4dda2` 的前端**不需要重新设计视觉方向**。

我建议把下一轮工作的目标正式定义成：

> **Snap / Room Commercial UI V1**

实施顺序：

**第一阶段：商业发布阻断**

1. Light Theme contrast
2. Login Dialog / Logout state
3. Accessibility semantics
4. Loading / Error / Empty / Offline

**第二阶段：Design System**
5. Typography
6. Interaction State
7. Component hierarchy
8. Content language

**第三阶段：品牌与高级视觉**
9. Brand identity
10. Empty/Skeleton illustrations
11. Motion
12. myMPD shell visual integration
13. Screenshot regression

做完这一轮，我会认为它才真正从**“高质量自用控制台”跨到“可以作为正式产品交付的前端”**。
